tagshelf

Sorts a music library by its tags, sets identical copies aside instead of deleting them, and can undo every run.

A command-line tool and terminal UI, written in Go, for Windows and Linux.

What it does

tagshelf sorts audio files into a music library by their tags. It moves each file to Artist\Album (Year)\NN - Title.ext.

Identical copies are set aside instead of deleted, and every move is recorded, so a run can be undone.

The command line is for running it. The terminal UI is for the files that need a person. It can also identify tracks by sound, handle cover art and build playlists.

Under the hood

  • Static builds for Windows (amd64) and Linux (amd64 and arm64), with no C library needed.
  • Never deletes an audio file. That is by design.
  • Dry run first. See what a run would do before it moves anything.
  • A database that migrates itself on upgrade, and keeps a backup of the old one.
  • Filename collisions that differ only in letter case are handled.
  • Characters Windows won't allow in names are replaced.
  • CI on GitHub and checksummed releases.

Why I built it

I always want my music collection organized so that any music player can show me the info I want.

I listen to too much music to not care about how I keep my music collection. Plus it felt natural with all the music players I have built over the years to help me learn programming.

Those were player-api in Go, go-player, a PHP player, and a Rails/TypeScript version, built between 2018 and 2023. tagshelf is where that thread led.

Get it

The releases page has downloads for Windows and Linux, and every release is checksummed. The source is on GitHub.
